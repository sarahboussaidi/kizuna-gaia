# GAIA 大地 — water, energy and agriculture for Tunisian farms

GAIA is a Kizuna Challenge 2026 prototype (Tunisia × Japan). It answers one question for a farm plot:
**which practices fit this land, how much water does the crop really need, and how much solar power does it take to pump only that?**

It pairs Tunisian practices (jessour, oases, olive groves) with Japanese ones (tanada terraces, satoyama,
solar sharing, kaizen), checks each one against the plot's real conditions, and refuses to recommend what does not fit.

## The nexus in one line

Crop water need (FAO-56) → pumping energy → solar pump size → a monthly water quota.
The pump is sized to the crop, not to the aquifer, so solar power does not become a reason to over-pump groundwater.

## Run it

The website needs no build and no install. Open `index.html` in a browser, or serve the folder:

```
npx serve .
```

The optional API is in [`backend/`](backend/README.md) (FastAPI):

```
cd backend
pip install -r requirements.txt
uvicorn gaia.main:app --reload      # http://127.0.0.1:8000/docs
pytest -q
```

| Page | What it does |
|---|---|
| `home.html` | Platform home |

The knowledge base lives in `js/kb.js`. After changing it, run `node tools/export_kb.js` to refresh `backend/data/knowledge.json`
(the same command exports the regional soil table to `backend/data/soil_tn.json`).

## Soil data

The SoilGrids REST API is paused by ISRIC, so the Land DNA reads soil in this order:

1. `soilEndpoint` in `js/gaia-core.js`, if you serve downloaded SoilGrids rasters for Tunisia;
2. the SoilGrids REST API (short timeout, in case it is back online);
3. `js/soil-tn.js`: typical topsoil values (texture, clay, organic carbon, 0–30 cm) for 21 Tunisian agro-ecological
   zones, compiled as orders of magnitude from HWSD v2 (FAO/IIASA) and SoilGrids 2.0. These are shown with
   confidence "low" and the zone name, never as a measurement of the parcel. A soil analysis replaces them.

## AI Lab with Claude (optional)

Without configuration the Lab answers from retrieval and templates. To add wording by Claude, grounded only in the
records and values the page retrieved:

```
cd backend
export ANTHROPIC_API_KEY=...        # never commit it
uvicorn gaia.main:app --reload
```

then, before `js/gaia-core.js` is loaded in `lab.html` (or in your own config script):

```html
<script>window.GAIA_CONFIG = { assistantEndpoint: 'http://127.0.0.1:8000/assistant' };</script>
```

The page still blocks any model sentence containing a number that is not in the evidence it sent.

## Plant health

The plant check never shows a diagnosis it did not compute.

1. The photo quality check (resolution, light, sharpness, share of leaf) always runs in the browser.
2. Tree and disease recognition run only when a model is installed: ONNX files plus a `manifest.json`
   in `models/gaia-vision/` for the website, or in `backend/models/gaia-vision/` (or `GAIA_MODEL_DIR`) for the API.
   The manifest sets the classes, the calibration temperature, the threshold under which GAIA says
   "I'm not sure", and the expert-validated advice cards. `health.html` shows an example manifest.
3. Without a model, the page says the model is not connected, and `POST /diagnose` answers `503 model_not_loaded`.
   With a model, `POST /diagnose` returns `ok`, `unsure`, `unsupported_tree` or `no_disease_model`.

No model is shipped yet: it still has to be trained on olive, date palm and citrus leaves and checked on Tunisian photos.

## Honest by design

- Every number shown is computed from a source or labelled as a simulation or a demonstration value.
- The four community profiles are illustrative scenarios, not real users.
- The sign-in page is a front-end mockup: nothing is sent or stored.
- Kaizen corrections stay on the device unless `feedbackEndpoint` is set in `js/gaia-core.js`.

## Design notes

Palette tokens are in `styles.css` (`--butter`, `--cream`, `--sage`, `--olive`, `--terracotta`, `--forest`…).
Use the `-deep` variants for text, because the base tones don't reach 4.5:1 contrast on cream.
Pages include a skip link, real buttons and labels, 44px touch targets and a `prefers-reduced-motion` path.
